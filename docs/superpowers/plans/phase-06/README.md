# 阶段 06 · 状态、存档、读档与回滚

## 目标与输入

让阶段 5 的双分支项目能够在明确的交互边界恢复，保存剧情而非宿主对象。以阶段 1 的兼容性矩阵确定行为，给 `default`、变量赋值和条件分支预留类型和作用域。

## 任务与交付

### P06-01 可持久化状态与版本契约

在 `format/` 定义 save schema、项目与构建身份、脚本位置、调用栈、变量、显示状态、等待中的菜单与输入状态。列出临时 GPU/音频句柄及任意原生对象等排除项。为兼容小版本、不同游戏内容和未知字段写处理规则。

### P06-02 写入、读取和恢复

在 `runtime-rust/` 实现先校验后替换的加载流程，采用临时文件及安全替换，失败时保留原档和当前状态。覆盖对白前、菜单中、选择后三个存档点。以测试 fixture 验证损坏、截断、版本冲突、不同构建及兼容小版本。

### P06-03 有界回滚与副作用

与 P06-02 共享 P06-01 的状态模型，定义可回滚交互点、历史深度、恢复后清除的输入和分支记录。为音频、文件写入等副作用区分重建、去重或不支持，记录限制。验证回滚后重新选择另一分支。

### P06-04 存档回归与样例

扩展双分支样例并提交固定版本的存档 fixture、失败提示和数据迁移说明。新增 `scripts/phase06-check.ps1`，在 CI 断言恢复事件、可读错误、损坏时无状态变更和回滚限制。

## 验收与交接

Windows 桌面复验三个保存点和两条路线。恢复后下一步轨迹应与未退出的对照执行一致。交给阶段 7 的是资源、音频状态恢复边界，交给阶段 8 的是 `default` 和受支持状态构造的确定契约。
