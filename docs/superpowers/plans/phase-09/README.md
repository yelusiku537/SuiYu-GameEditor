# 阶段 09 · 最小编辑器

## 目标与输入

创作者可在桌面创建或打开项目、修改脚本、增量编译、定位错误并启动 Rust 预览。阶段 4–5 的命令和诊断是依赖，MVP 验收项目同时消费阶段 6、7 的存读档和基础转场。以 MyGo Native UI 为默认，工具桥保持界面无关。

## 任务与交付

### P09-01 MyGo 能力核验与项目外壳

核对固定 MyGo 版本和窗口、布局、绘制、剪贴板及 IME 支持。在 `editor-go/` 提供新建和打开、文件树、工具栏、资源浏览、属性面板、编译输出、运行日志和预览按钮。独立的树、属性和编辑组件各带最小示例、明确 API 和自动测试。

### P09-02 原生代码编辑原型与比较

单独验证中文 IME 组合提交、选区、撤销重做、剪贴板、高亮、诊断、跳转和大文件滚动。实测前记录目标脚本规模、输入延迟、滚动目标及稳定性标准。原生表现不达标时，用 ADR 和实测决定是否引入 MyGo Web frontend + Monaco/CodeMirror。记录冷启动、空闲/峰值内存、CPU、输入延迟、编译响应和打包体积，标注未测项。

### P09-03 增量编译、保存与预览会话

接入 Go 工具和 Rust 预览进程。定义诊断行列映射、项目文件安全保存、日志和退出状态、终止重启与进程回收。调试协议可选、低频、有版本。测试含路径中空格、Unicode、编译失败、预览崩溃和关闭编辑器。

### P09-04 从空目录到 MVP 的流程验收

交付模板和 3–5 分钟短剧情，包含两名角色、三句以上对白、双选项、多个 label 及存读档。记录从空目录创建、打开 Unicode 路径、输入中文、定位编译错误、修复、重新预览和完成剧情的操作。核心检查进入 CI，中文 IME 与桌面性能保留环境记录。

## 验收与交接

新增 `scripts/phase09-check.ps1`，覆盖编辑器集成及共享 MVP 回归。Windows 实测默认路径使用 MyGo Native UI，并记录实际的界面方案与比较结果。交给后续阶段的是预览控制、编辑组件和诊断契约。
