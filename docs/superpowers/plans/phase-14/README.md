# 阶段 14 · 协作、插件生态和稳定发布

## 目标与输入

将阶段 4、8、10–12 的公开接口与兼容性边界整理成可维护规范，用阶段 13 提供的发布候选和门禁交付稳定版本。

## 任务与交付

### P14-01 公开规范、变更日志和迁移

发布脚本语言、游戏包、效果 API、插件 manifest 和 UI 组件 API；标明已稳定接口、支持版本和弃用规则。同步兼容性矩阵、变更日志、存档及项目迁移指南，给出错误版本案例。

### P14-02 官方插件样例与导入门禁

提供资源插件、声明式效果、Go/WASM 效果、UI 风格四类示例，明确各自的权限和发布材料。CI 编译并加载官方 WASM 效果，检查默认无宿主文件系统和网络能力，并在导入阶段验证版本与能力。用一次新贡献者试跑确认文档可从空项目复现。

### P14-03 贡献和安全报告流程

补充 Issue 模板、支持范围、兼容性缺陷所需信息和私下漏洞报告入口。记录维护人如何认领、处理、复现和发布修复，以及响应交接。文档与插件样例和发布准备可并行完成。

### P14-04 构建、签名和发布验收

定义正式版本号、产物清单、目标平台、校验和、签名与验签步骤、回退路径。对发布包检查许可证、依赖、大小、启动、内存和回归。包清单排除编辑器缓存、`target` 与个人配置。新增 `scripts/phase14-release-check.ps1`，从候选版生成可复核的验收记录。

## 验收与交接

从干净环境复现官方样例插件，并验证兼容与不兼容的导入行为。发布前用目标设备复验下载产物、签名、启动和 MVP 剧情，记录每项验收、版本及回退方式。将问题归入下一版本路线图。
