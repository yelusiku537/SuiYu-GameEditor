# 阶段 13 · 性能、内存与发布优化

## 目标与输入

沿用阶段 7 的对照方法，在固定规模和设备上定位实际瓶颈并检验发布候选。纳入阶段 9 的编辑器与游戏进程隔离和阶段 10–12 的效果及 UI 回归场景。

## 任务与交付

### P13-01 三种规模与成文的比较方法

在 `benchmarks/` 提供小型、中型、资源较重三个测试项目，固定版本、硬件、OS、分辨率、资源及脚本路径。区分冷/热启动与首次/重复加载，记录重复次数、统计量、误差带及机器可读字段。发布优化前样本和本轮验收阈值。

### P13-02 运行时热点与资源预算

依据采样排序图片解码与纹理上传、缓存、文本布局、UI 重绘、脚本临时分配、音频缓冲。对所选热点逐项保存前后数据并运行行为回归。配置 CPU/GPU 等资源预算，验证超预算告警或安全拒绝加载。

### P13-03 编译、打包和进程开销

测量包索引、随机读取、预加载、编译增量缓存、打包时间及编辑器和游戏进程占用。选定有数据支持的优化，比较启动、全量和增量构建、包体积及输出一致性。用同一项目同条件复验。

### P13-04 基准入口及发布候选验收

新增 `scripts/phase13-benchmark.ps1`，输出机器可读结果、版本与日志。记录两实现相同场景下的 CPU 内存、GPU 纹理、帧时间、编译与打包；单独记录不可直接比较的场景。报告逐指标列分母、前后值和测量误差。

## 验收与交接

三种规模均可自动执行，优化项有前后证据且回归通过。对外性能结论仅引用达到预先阈值的具体指标。发布阶段消费资源门禁、支持平台范围及候选包测量报告。
