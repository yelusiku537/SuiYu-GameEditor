# 阶段 01 · Ren'Py 源码分析与行为地图

## 目标与输入

为新引擎的语义决策提供可复查证据。沿用阶段 0 的固定 SDK、对照提交及来源规则。每个行为文档记录环境、上游代码路径与符号、fixture、输入序列、预期与实际观察、限制和目标兼容等级。

## 任务与交付

### P01-01 对照运行约定与启动链

跟踪游戏启动、`.rpy` 加载和编译、初始化与交互循环。定义 fixture 命名、事件记录格式和复验入口，将 SDK、用户存档与产物放入隔离目录。交付 `docs/compatibility/` 的写作约定、启动链文档和最小启动 fixture。

### P01-02 控制流、变量和对白

按 P01-01 的模板，为 `label`、`jump`、`call`、`return`、`say`、`menu`、`define`、`default` 建文档和独立可运行 fixture。观察调用返回位置、入口、嵌套调用、菜单继续位置、初始化及读档下默认值。交付正常和边界路径的轨迹。

### P01-03 演出、存档和复杂特性

与 P01-02 并行，覆盖 `scene`、`show`、`hide` 的清空、同标签替换与层序。为音频、转场、缓存、存读档、回滚记录可观察结果。单列 screen、ATL、嵌入 Python 的边界、静态可识别子集和待研究问题，用小样例界定差异。

### P01-04 汇总兼容性矩阵

在 `docs/compatibility/COMPATIBILITY_MATRIX.md` 按功能标注“必须兼容”“允许不同”“暂不支持”，链接源证据、fixture 和负责阶段。保留有分歧的观察与复测条件，让阶段 4 和阶段 8 能引用同一语义决策。

## 验收与交接

新增 `scripts/phase01-check.ps1` 作为固定 SDK fixture 检查入口。至少 10 个核心行为分别具备证据、可运行 fixture 和明确等级。GUI 行为记录观察方法，自动轨迹与人工观察各自标明。交给阶段 2–5 的是控制流、资源、诊断、事件和源码定位相关决策，给阶段 8 的是转换分级依据。
