## 认领与验收

- 在 GitHub TODO 合集里评论 `认领 P01-01`，维护者可按任务拆分子 Issue。开工前核对任务依赖，并在线程里标出尚未就绪的输入。
- PR 标题或正文保留任务编号，同步列出交付路径、实际命令、退出码或证据链接及已知限制。同一任务需要多份 PR 时，合并完整交付后再勾选。
- 每阶段的验收记录应有可运行代码或可复现研究产物、自动测试、样例、执行结果及交给下一阶段的输入。新增外部材料先登记 [第三方来源](../../../LICENSES/THIRD_PARTY.md)。
- 阶段 1–14 验收小节所列的新脚本是实施任务的一部分。PR 应提供可从仓库根目录调用的命令，将缓存和测试产物放在仓库外，并记录 Windows 原生或 CI 的桌面证据。若取代建议入口，同一 PR 更新阶段计划及验收记录。
- 主线先完成阶段 5 的可玩闭环；第一版 MVP 还需阶段 6 的存读档、阶段 7 的基础淡入淡出以及阶段 9 的编辑器预览。阶段 8 是迁移交付，可在语义边界确定后与编辑器工作并行。
