# 阶段 02 · 游戏包格式与公共协议 v0

## 目标与输入

将 Go 产物和 Rust 消费端固定在一份版本化契约上。输入为阶段 1 的脚本入口、资源标识、诊断定位需求，以及阶段 0 的 Go/Rust 工程。产物只定义游戏包边界，剧情指令的完整语义由阶段 4 冻结。

## 任务与交付

### P02-01 规范与最小包 ADR

在 `format/` 写 manifest、入口、最低引擎版本、脚本区、source map、资源与音频索引、项目元数据。决定容器布局、字节序、字符串编码、数值与浮点规则、相对路径规范、资源 ID、哈希和大小上限。明确未知可选字段、未知必需能力、未知版本和重叠区段的处理。附逐字段可读的完整例包。

### P02-02 Go 编解码器

按 P02-01 实现显式校验和稳定序列化，定义资源顺序、时间字段等可复现构建规则。错误含输入区段和稳定类型，编码失败不留部分包。交付 Go 往返、确定性输出和坏数据测试。

### P02-03 Rust 读取与源码定位

与 P02-02 并行，按规范验证头、版本、长度、范围和内容哈希，失败返回结构化错误。实现位置到文件、行、列的映射，区分缺失与非法映射。交付最小 Go 产物读取测试和 Rust 校验 fixture。

### P02-04 跨语言金样和版本门禁

保存最小包、Unicode 路径、多资源及源码映射金样，记录生成命令与预期解析结果。加入截断、缺文件、未知版本、哈希错误和超限包。每次更新金样说明规范差异，并提交版本变更或迁移说明。

## 验收与交接

新增 `scripts/phase02-check.ps1`。重复构建同一输入得到一致字节，Go 输出由 Rust 读取后与预期字段对照一致，损坏输入得到明确错误，模拟运行错误定位到原始行列。交给阶段 3 的是可读取的带图包，交给阶段 4 的是脚本区和 source map 契约。
